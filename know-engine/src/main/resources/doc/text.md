测试方案

第一层：离线自动化（开发阶段）
- Top-K 命中率：用户问题在前 K 个推荐结果中是否包含正确答案 — 一般 Top-5 ≥ 85% 即可
- 无效回答率：用户点了"不满意"或"没有帮助"的占比 — 目标 < 10%
- 这些不需要人工标注，系统日志就能算

第二层：线上指标（上线后）
- 解决率（Resolution Rate）：用户提问后是否在 N 轮内关闭会话
- 转人工率（Escalation Rate）：多少对话被转接给人工 — 目标 < 30%
- 用户满意度（CSAT）：会话结束后的打分

项目：通用 RAG 智能客服系统
基于 Spring Boot、LangChain4j 与 Reactor 响应式架构，面向企业内部业务场景设计并实现通用 RAG 智能客服系统。系统整合知识库文档管理、多源异构数据检索、LLM 问题理解、重排序增强与 SSE 流式
对话能力，支持企业业务知识的高效接入、检索增强问答和答案溯源。
技术栈： Spring Boot、LangChain4j、Reactor、Elasticsearch、MySQL、Redis、MinIO、XXL-JOB、BGE-Reranker
主要工作：
1. 设计并实现 Agent 流式任务管理器，支持任务注册、运行状态检测、主动停止、资源清理等能力；基于 Redis trySet + TTL 实现会话级任务占用控制，避免多实例部署下同一会话重复生成；通过 Redis
   Pub/Sub 广播停止指令，实现跨实例中断 SSE 流式输出
2. 封装统一文档处理管道，支持 PDF、DOCX、Markdown、Excel/CSV 等多格式文档解析；实现自定义 Markdown 标题分片器、重叠段落分片、父子文档分片等语义切分策略；采用本地消息表实现 MySQL 与
   Elasticsearch 双写一致性，确保文档元数据、切片结果与向量索引在异常重试场景下最终一致
3. 设计 RAG 查询增强链路，基于 LLM 实现用户问题改写与查询路由，将自然语言请求按意图分发至 Elasticsearch 向量检索、全文检索、MySQL Text-to-SQL 等数据源；引入 BGE-Reranker 对多路召回结
   果进行二次打分、Top-K 聚合和引用信息回写，提升复杂业务问答的召回准确率、答案相关性和可追溯性
4. 基于 Reactor Flux 和 SSE 实现端到端流式对话，支持进度事件、Token 级输出、引用信息推送和任务中断，优化用户在 RAG 检索、重排和生成阶段的等待体验
